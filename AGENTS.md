## AFK execution

For runner IMPLEMENT, FIX, or REVIEW assignments, read `afk-Codex/project-policy.md` before work. It defines the approved issue scope, document context, verification, and role-specific audit behavior. REVIEW remains strictly read-only; documentation maintenance instructions below never authorize reviewer writes. Preserve the runner's exact JSON output contract and put elapsed time inside its summary.

## Agent skills

### Issue tracker
Track work in GitHub Issues. Before issue operations, read `docs/agents/issue-tracker.md`.

### Triage labels
Use the five canonical labels. Before triage, read `docs/agents/triage-labels.md`.

### Domain docs
Use a single-context layout. Before exploring the codebase, read `docs/agents/domain.md`.

### Architectural decisions
When a material architectural decision is made, record it in `docs/adr/decisions.md` in the same turn with a concise decision, rationale, and status. Record only decisions actually made; preserve superseded entries with a reference to their replacement.

## Tooling documentation

When using or adopting a tool, skill, language, framework, library, database, or service for this project, update `docs/tooling.md` in the same turn. Record its purpose and whether it is used, configured, or planned. Keep entries current when tools are replaced or removed; record versions only when verified.
